# ADR-0008 — Generated l10n output into `lib/l10n` (Flutter ≥ 3.44)

Status: Accepted

## Context

Flutter 3.44 removed `synthetic-package: true` from `flutter gen-l10n`, so the
generated `AppLocalizations` classes can no longer be imported from
`package:flutter_gen`. All in-repo guidance assumed that import path; failing
to pin the new location would break every `context.l10n` call.

## Decision

- `l10n.yaml` generates into `lib/l10n/`:
  `app_localizations.dart`, `app_localizations_en.dart`, `app_localizations_hi.dart`.
- Canonical import is `package:onebit/l10n/app_localizations.dart`; no
  flutter_gen imports anywhere.
- A single `BuildContextX.l10n` extension (`core/extensions`) is the only
  accessor; features never import the generated files directly.
- Locale switching is driven by `LocaleController` (`shared/localization`) and
  wired to `MaterialApp.locale`; `supportedLocales` lists en + hi.

## Consequences

- `flutter gen-l10n` output is versioned and visible in the repo; the generated
  files are plain Dart and analyzable.
- The l10n accessor is swappable (e.g., a custom loader) without touching
  feature code.
- Cost: regeneration overwrites `lib/l10n` — never hand-edit those files.
